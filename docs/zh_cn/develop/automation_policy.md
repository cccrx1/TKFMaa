# 自动化策略

本文说明任务的目标、风险和边界，不替代任务流程文档，也不记录具体 ROI。

## 统一策略

| 风险 | 默认行为                       | 约束                                 |
| ---- | ------------------------------ | ------------------------------------ |
| 低   | 导航、领取、收取、关闭已知弹窗 | 识别失败停止或返回安全页面           |
| 中   | 使用已配置队伍和用户选择执行   | 不替换队伍，不猜测缺失条件           |
| 高   | 仅处理用户明确配置的目标       | 限制数量、次数和资源；状态不明时退出 |

所有任务都遵循“识别 -> 动作 -> 再识别”。点击成功不能仅凭动作返回值判断，必须确认页面状态。

## 收取类任务

适用于好友体力、奖励领取和炼金订单。目标是收取已存在的奖励或订单，不改变用户配置。识别失败时允许停止或返回主界面，不得盲点继续。

## 每日派遣

使用预先编好的队伍派出闲置栏位，不自动编队、补充角色或替换预编队。预编队不满足条件时保留闲置队伍并安全退出。

## 商城购买

仅购买用户在选项中指定的商品，扫描时跳过售罄商品。不得扩大商品匹配范围，不得在目标或购买数量不明确时购买。必须确认商品名称、数量、购买按钮和购买后状态。

## 消耗体力

先确认活动、关卡和体力状态，再执行扫荡或战斗。体力药和魔晶石由独立选项控制，未开启时体力不足应安全退出。恢复次数、使用数量和购买次数必须有上限，购买后不能重复购买同一轮恢复。

## 调教

按筛选条件处理房间，优先使用普通或活动道具；珍贵道具需要单独开启。道具范围不明确、次数不足或目标识别失败时退出。

## 全境征才

处理四个招募栏位，按照已实现的词条和时间策略招募。立即招募由独立选项控制，并限制循环次数和资源消耗。词条、按钮或结果页不确定时不得继续消耗资源。

## 不覆盖的行为

挑战活动、未采集页面、未验证的客户端版本和没有明确目标的资源消耗，不应由 AI 根据文档推测实现。应先采集页面并更新对应任务流程文档。
