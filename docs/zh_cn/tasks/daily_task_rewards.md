# 奖励领取（DailyTaskRewards）

入口节点：`DailyTaskRewardsStart`；实现文件：`assets/resource/pipeline/daily_task_rewards.json`、`agent/completion.py`。

## 前置状态

- 游戏位于主界面，任务页面已解锁。
- 每日、每周、每月、个人、活动和协会页签可能没有可领取奖励。

## 主流程

1. 从主界面打开任务页面并选择每日页签。
2. 同时确认任务页标题、可领取文本和一键领取按钮；命中后点击并关闭奖励或仓库堆叠上限弹窗。
3. 依次处理每周、每月、个人、活动和协会页签。
4. 每页均确认选中标签、任务标题和领取按钮，并连续两次确认按钮不可领取且列表无可领取文本后才切页。
5. 六页处理后重新从每日开始复查一轮，共用每页三次领取上限，第二轮通过后返回主界面。

```mermaid
flowchart TD
    Start[开始任务，加载或异常起点先恢复主界面] --> Open[打开任务页]
    Open --> Daily[选择每日页签]

    Check -->|仓库堆叠上限提示| Full[确认上限提示]
    Check -->|展开或紧凑奖励正文| Reward[按对应布局确认奖励]
    Check -->|其他确定或确认按钮| Fallback[识别按钮并关闭弹窗]
    Full --> Check
    Reward --> Check
    Fallback --> Check
    Check -->|任务标题、选中标签、可领取、按钮同时命中且未达上限| Claim[点击一键领取，每页最多 3 次]
    Claim --> Check
    Check -->|页面与选中标签确认，按钮不可领取且无可领取文字| Verify[间隔后复查当前页]
    Verify -->|仍无目标且无奖励弹窗| Last{当前是协会页签?}
    Verify -->|有可领取目标且未达上限| Claim
    Verify -->|无法确认或领取次数耗尽仍有目标| Fail
    Last -->|否| Next[识别并选择下一个页签]
    Next --> Check
    Last -->|是，首轮结束| Round[开始第二轮六页复查]
    Round --> Daily
    Last -->|是，第二轮完成| Back[点击返回主界面]
    Check -->|候选识别超时| Fail[任务失败，不认定全部领取完成]
    Next -->|页签识别超时| Fail
    Back --> Confirm[公共主界面结束确认]
    Confirm -->|识别成功| Done[停止任务]

```

页签顺序固定为 **每日 → 每周 → 每月 → 个人 → 活动 → 协会**。领取或关闭弹窗后重查当前页签，
每页通过两次完成检查才进入下一页；第二轮复用相同领取节点，不重置领取次数。
到达上限仍有目标时失败，不能通过切页掩盖未完成；页签点击未生效时有限重选，累计最多四次。
公共结束确认见 [公共主界面恢复](common_navigation.md)。

## 页面识别

| 页面状态     | 识别目标                                 | 识别方式 | ROI/素材                                                |
| ------------ | ---------------------------------------- | -------- | ------------------------------------------------------- |
| 任务页面     | 任务                                     | OCR      | 页面标题区                                              |
| 页签         | 每日、每周、每月、个人、活动、协会       | OCR      | 两行页签区域                                            |
| 可领取状态   | 可领取                                   | OCR      | 任务列表区域                                            |
| 领取按钮     | 一键领取                                 | OCR      | 页面底部按钮区                                          |
| 普通奖励弹窗 | 奖励已增加至仓库                         | OCR      | 按正文纵坐标区分紧凑和展开布局                          |
| 仓库上限弹窗 | 可领取的物品已超过堆叠上限，请至仓库确认 | OCR      | 页面中部提示区                                          |
| 弹窗按钮兜底 | 确定、确认                               | OCR      | 页面中部至下部按钮区，`DailyTaskRewardsCloseClaimPopup` |

## 异常与分支

- 返回主界面不再等待全屏静止，交给公共结束确认；入口通过公共恢复关闭礼包，避免被登录遗留页面阻挡。
- 某页签无可领取任务时，通过当前页完成检查后进入下一页签，不点击固定位置。
- 领取动作使用 And 组合页面标题、可领取文本和按钮，并通过 `box_index: 2` 点击按钮识别框。
- 每个页签限制最大领取次数。普通奖励弹窗按“奖励已增加至仓库”的纵坐标区分紧凑和展开布局，仓库上限弹窗
  识别完整提示正文；两者均点击各自稳定的确认区域，再返回当前页签继续判断。
- `DailyTaskRewardsCloseClaimPopup` 继续以“确定/确认”OCR 作为兜底，避免未知弹窗布局阻挡后续页签点击。
- `TaskCompletionGuard` 在同一截图中核对标题、选中标签颜色、领取按钮文字及不可领取颜色，
  同时排除可领取文本与奖励/仓库上限正文。未执行成功或被禁用的必要检查一律拒绝完成。
  正文、标签或按钮样式变化时应重新采集，不能只保留“未识别到可领取”的负面依据。

## 完成状态

- 正常目标：检查六个页签并领取当前可领取奖励。
- 成功条件：两轮六页均经当前页完成检查后返回并确认主界面。
- 每页最多领取三次；上限耗尽仍有目标、仓库满阻止领取或无法确认页面时失败并保留页面。
- 正常完成返回游戏主界面；完成检测不保证不可见任务或未知客户端布局均被识别。
