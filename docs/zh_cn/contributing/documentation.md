# 文档与验证资料

功能说明回答“程序如何工作”，测试记录回答“某次测试证明了什么”。两者分开维护，不能用一次本机通过替代功能约束，也不能把文档流程图当作实测证据。

## 哪些内容随仓库提交

| 内容                                     | 保存位置                     | 是否提交远端               |
| ---------------------------------------- | ---------------------------- | -------------------------- |
| 安装说明、协作规则、通用开发与构建规范   | README、AGENTS、contributing | 是                         |
| 功能前提、选项、页面流程、结束条件和限制 | tasks                        | 是                         |
| 空白任务、变更请求和验证模板             | templates                    | 是，不填写个人数据         |
| 面向使用者的版本变化、兼容要求和已知问题 | releases                     | 是，绑定具体版本           |
| 每次本机测试过程、失败排查、设备细节     | 本地 records                 | 否                         |
| 个人环境、工作笔记                       | 本地 develop                 | 否                         |
| 原始日志、截图、账号配置、模型和扫描缓存 | 被忽略的本地路径             | 否，不自动上传             |
| 为代码评审准备的脱敏验证摘要             | PR 正文；必要时 Issue        | 获得相应远端操作授权后提交 |

“适合公开”不等于“已经授权上传”。提交、推送、创建 PR、发布及上传附件仍遵守根目录 AGENTS.md 的授权规则。
需要公开证据时，只选择与问题相关的日志片段或截图，移除账号、令牌、设备序列号及个人路径。不得强制暂存被忽略的记录目录。

## 每次测试如何记录

使用[验证记录模板](../templates/verification.md)在本地 `docs/zh_cn/records/` 创建记录，建议文件名为 `YYYY-MM-DD_任务_主题.md`。
记录源码提交及未提交改动、客户端版本或包来源、测试环境、选项、覆盖路径、结果和证据位置。
成功、失败、受阻、未执行分别标记；没有连接设备就明确写“未进行实机验证”。重复失败或已知问题也要保留，不只记录成功结果。

提交评审时可从本地记录提取简短摘要，说明相关环境、执行内容、结果和未覆盖分支。版本说明面向使用者，只写影响其安装、升级或使用判断的信息，例如兼容要求、已知问题和必要操作；不写维护者本机测试过程、设备细节或未覆盖分支。若特定限制确实影响使用者，应描述限制本身，不以某台设备的测试结果代替。
纯文档检查记为文档检查，不建立虚假的“实机通过”记录。

## 唯一维护位置

- 协作授权边界：根目录 AGENTS.md；专题文档引用它，不另建相互冲突的权限规则。
- 实现与参数：当前源码及配置；任务说明记录行为、约束和关键入口，不复制全部 ROI 或节点表。
- 版本：以[运行环境与版本](runtime.md)列出的配置源为准；版本说明表变更时一并核对来源。
- 通用页面恢复：公共任务说明；其他任务通过链接复用。
- 当期活动与关卡：源 YAML；历史活动和测试快照保留本地。
- 本地缓存：只用于发现线索；应记录生成时间、源码提交和扫描范围，失效时核对源码，不自动覆盖已有缓存。

## 编写与维护方式

规则使用“触发条件 → 操作 → 完成证据 → 受阻处理”的表达。稳定规则写入协作或专题规范；本次请求的目标、范围、限制和验收条件使用[变更请求模板](../templates/change_request.md)。
新功能使用[任务模板](../templates/task.md)；复杂任务可增加子流程，简单任务无需空填不适用章节。
已有文档逐步迁移，保留已知异常、资源边界和恢复限制，不为了精简删掉失败分支。

公开文档只链接随仓库存在的文件或公开网址。本地资料可以按路径约定说明用途，但不能成为完成开发所必需的唯一说明来源。
修改文档后检查链接、路径、代码引用和格式；修改规则时检查原规则是否已保留或有明确替代，避免只删篇幅却丢失约束。
